## 2.1 What "learning" means

Machine learning replaces hand-written rules with a **parameterized function** fit to data. Formally: given examples `(xᵢ, yᵢ)` drawn from some distribution `D`, choose parameters θ to minimize the **expected loss** `E_(x,y)~D [ L(f(x;θ), y) ]`. We can't see `D`, only a finite sample, so we minimize the **empirical risk** (average training loss) and hope it *generalizes*. Almost every concept this week — validation sets, regularization, bias-variance — is about the gap between those two quantities.

The three ingredients of any ML system:
1. **Model / hypothesis class** — what functions are possible (linear, tree, neural net).
2. **Loss** — what "wrong" costs (MSE, cross-entropy, hinge).
3. **Optimizer** — how we search (closed form, gradient descent, Adam).

Learning paradigms: **supervised** (labeled pairs), **unsupervised / self-supervised** (structure from unlabeled data — LLM pretraining is self-supervised: the label is the next token), and **reinforcement learning** (learn from rewards of actions — used in RLHF and reasoning models).

## 2.2 Linear and logistic regression

**Linear regression**: `ŷ = wᵀx + b`, loss = mean squared error `(1/n) Σ (ŷᵢ − yᵢ)²`. It has a closed-form solution (`w = (XᵀX)⁻¹Xᵀy`) but we'll solve it with gradient descent because that's what scales: `∇w MSE = (2/n) Xᵀ(Xw − y)`.

**Logistic regression** (binary classification): `p = σ(wᵀx + b)` with `σ(z) = 1/(1+e^{−z})`. Loss = **binary cross-entropy** `−[y log p + (1−y) log(1−p)]`. Beautiful fact: its gradient is `(p − y)·x` — "prediction minus truth, times input". The same form appears for softmax + cross-entropy with many classes: `∂L/∂logits = softmax(z) − onehot(y)`. You will see this again inside every LLM.

MSE corresponds to maximum likelihood under Gaussian noise; cross-entropy corresponds to maximum likelihood under a categorical/Bernoulli model. Losses aren't arbitrary — they encode assumptions about the data.

## 2.3 Gradient descent variants

- **Batch GD**: gradient over the full dataset per step. Accurate, slow, infeasible at scale.
- **Stochastic GD (SGD)**: one example per step. Noisy but cheap.
- **Mini-batch SGD**: from about 32 to thousands of examples per step (LLM pretraining batches hold millions of tokens). The standard. The noise is a feature — it acts as implicit regularization and helps escape sharp minima.

The **learning rate** η is the most important hyperparameter. Too high → divergence or oscillation; too low → slow progress and getting stuck. Modern practice uses **schedules**: linear **warmup** (avoid early instability) followed by **cosine decay** or linear decay. One **epoch** = one pass through the training data; LLMs are often trained for ~1 epoch over enormous corpora.

Feature scaling matters: if one feature ranges 0–1 and another 0–1,000,000, the loss surface is a stretched valley and GD zig-zags. Standardize inputs (zero mean, unit variance).

## 2.4 Generalization, overfitting and bias–variance

- **Underfitting (high bias)**: model too simple; training and validation error both high.
- **Overfitting (high variance)**: model memorizes noise; training error low, validation error high.

Classical view: test error = bias² + variance + irreducible noise, with a U-shaped curve vs model complexity. Modern deep learning complicates this with **double descent**: very over-parameterized models can generalize well again past the interpolation threshold. The practical takeaway: *measure*, don't assume.

Data splits:
- **Train**: fit parameters.
- **Validation (dev)**: choose hyperparameters, early stopping, model selection.
- **Test**: touched once at the end for an unbiased estimate. Leaking test data into decisions — even by repeated peeking — inflates results. This is the same problem as **benchmark contamination** for LLMs (Week 12).
- **k-fold cross-validation** for small datasets.

Watch for **data leakage**: features that encode the label, duplicates across splits, time-series split randomly instead of chronologically, normalization statistics computed on the full dataset.

## 2.5 Regularization

Techniques that reduce variance:
- **L2 / weight decay**: add `λ‖w‖²` to the loss; pulls weights toward zero. In AdamW, decay is *decoupled* from the gradient update.
- **L1**: `λ‖w‖₁`; encourages sparsity.
- **Early stopping**: stop when validation loss stops improving.
- **Dropout**: randomly zero activations during training (Week 3).
- **Data augmentation** and simply **more data** — usually the most effective regularizer of all.

## 2.6 Evaluation metrics

Accuracy is misleading on imbalanced data (99% accuracy predicting "not fraud" every time). Know the confusion matrix:

- **Precision** = TP / (TP + FP) — "when I say yes, how often am I right?"
- **Recall** = TP / (TP + FN) — "of the real yeses, how many did I catch?"
- **F1** = harmonic mean `2PR/(P+R)`.
- **ROC-AUC**: probability a random positive is scored above a random negative; threshold-independent.
- **Calibration**: does a predicted 0.8 come true 80% of the time? Critical when downstream logic uses probabilities (e.g. routing low-confidence LLM outputs to humans).
- Regression: MAE, RMSE, R².

Choose the metric from the **cost of errors** in the product. A spam filter cares about false positives (losing real mail); a cancer screen cares about recall.

## 2.7 Classical models worth knowing

You won't build them daily, but interviewers ask and they're often the right tool for tabular data:
- **k-NN**: predict from nearest neighbors. Same idea as vector retrieval in RAG.
- **Decision trees** and ensembles: **random forests** (bagging), **gradient-boosted trees** (XGBoost/LightGBM) — still state of the art on many tabular problems.
- **SVMs**: max-margin classifiers with kernels.
- **k-means** clustering and **PCA** for unsupervised structure.

An AI engineer's judgement includes knowing when *not* to use an LLM: a gradient-boosted model on structured warehouse data can be cheaper, faster, more accurate and more explainable.

## 2.8 Week summary

You can frame a problem as model + loss + optimizer, implement gradient descent for linear and logistic regression, diagnose over/underfitting from learning curves, design leak-free splits, and choose metrics that reflect real costs.
