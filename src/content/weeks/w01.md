## 1.1 Why an AI engineer needs the math

You don't need to be a mathematician to ship AI systems, but you do need to *read* the math fluently. Every serious design decision you will make — picking a learning rate, deciding whether to quantize a model, debugging a NaN loss, estimating GPU cost — reduces to a handful of ideas from **linear algebra**, **calculus** and **probability**. This week is the vocabulary for the rest of the course.

Mental model: a neural network is a **function** `f(x; θ)` made of matrix multiplications and simple nonlinearities. Training means **adjusting θ (millions to trillions of numbers) to minimize a loss**, using **gradients** computed by the chain rule. The loss is almost always a **negative log-probability**. That's the whole game — linear algebra describes the function, calculus describes how to improve it, probability describes what "good" means.

## 1.2 Vectors, matrices and shapes

A **vector** is an ordered list of numbers; in ML it usually represents a data point or a learned representation (an *embedding*). A **matrix** is a 2-D array; a **tensor** generalizes to N dimensions. In practice, 80% of deep-learning bugs are *shape bugs*, so always write shapes next to your code.

Key operations:

- **Dot product** `a · b = Σ aᵢbᵢ`. Geometrically `|a||b|cos θ`, so it measures *alignment*. Attention, similarity search and logits are all dot products.
- **Cosine similarity** `(a · b) / (|a||b|)` — dot product after normalizing length. Ranges −1…1. The default metric for embeddings.
- **Matrix multiply** `(m×k) @ (k×n) → (m×n)`. Each output entry is a dot product of a row and a column. Cost ≈ `2·m·k·n` FLOPs (one multiply + one add per term) — memorize this; you'll use it to estimate training compute in Week 6.
- **Transpose** `Aᵀ` swaps rows and columns. `(AB)ᵀ = BᵀAᵀ`.
- **Broadcasting**: NumPy/PyTorch stretch dimensions of size 1 to match. `(32, 512) + (512,)` adds a bias to every row. Powerful and a top source of silent bugs.

A linear layer is just `y = xW + b` with `x: (batch, d_in)`, `W: (d_in, d_out)`, `b: (d_out,)`.

```python
import numpy as np
x = np.random.randn(32, 784)      # batch of 32 flattened 28x28 images
W = np.random.randn(784, 128) * 0.01
b = np.zeros(128)
h = x @ W + b                     # (32, 128)
```

## 1.3 Linear algebra ideas you'll meet again

- **Linear transformation**: a matrix maps vectors to vectors while preserving addition and scaling. Neural nets alternate linear maps with nonlinearities; without the nonlinearities, a deep stack collapses into one matrix.
- **Rank**: the number of linearly independent rows/columns — the "true dimensionality" of the map. **LoRA** (Week 7) fine-tunes models by learning a *low-rank* update `ΔW = BA` with `B: (d, r)`, `A: (r, d)` and `r ≪ d`.
- **Eigenvectors / SVD**: `A = UΣVᵀ` decomposes any matrix into rotations and scalings. The singular values tell you how much "signal" each direction carries. Used in PCA, compression and analysis of trained weights.
- **Norms**: `‖x‖₂ = √Σxᵢ²`. Weight decay penalizes weight norms; gradient clipping caps gradient norms; LayerNorm/RMSNorm normalize activation scale.

## 1.4 Calculus: derivatives, gradients, chain rule

The **derivative** `f'(x)` is the slope — how much output changes per unit change in input. For a function of many inputs, the **gradient** `∇f` is the vector of partial derivatives; it points in the direction of **steepest increase**. So to *decrease* a loss we step the other way:

```
θ ← θ − η · ∇θ L(θ)        # gradient descent, η = learning rate
```

The **chain rule** is the engine of deep learning. If `y = f(g(x))`, then `dy/dx = f'(g(x)) · g'(x)`. A network is a long composition of functions, so the gradient of the loss with respect to an early weight is a *product* of local derivatives along the path. **Backpropagation** (Week 3) is just the chain rule applied efficiently from output to input, reusing intermediate results.

Two consequences to remember:
1. If many local derivatives are < 1, their product shrinks toward 0 → **vanishing gradients**. If > 1, it explodes → **exploding gradients**. Residual connections and normalization exist largely to fix this.
2. Gradients are **local** information. Gradient descent finds a point where the slope is ~0, which in high dimensions is usually a good-enough region rather than a global optimum.

Useful derivatives: `d/dx eˣ = eˣ`, `d/dx ln x = 1/x`, sigmoid `σ'(x) = σ(x)(1−σ(x))`, ReLU' = 1 if x>0 else 0.

## 1.5 Probability and information

A language model is a probability distribution over the next token. You need:

- **Random variables, distributions, expectation** `E[X] = Σ x·p(x)`; **variance** `E[(X−μ)²]`.
- **Conditional probability** `p(A|B) = p(A,B)/p(B)` and **Bayes' rule** `p(A|B) = p(B|A)p(A)/p(B)`.
- **Chain rule of probability**: `p(x₁…xₙ) = Π p(xᵢ | x₁…xᵢ₋₁)`. This is *exactly* how autoregressive LLMs factor text.
- **Softmax** turns arbitrary scores (logits) `z` into a distribution: `softmax(z)ᵢ = e^{zᵢ} / Σⱼ e^{zⱼ}`. Subtract `max(z)` first for numerical stability — mathematically identical, prevents overflow.
- **Maximum likelihood**: choose θ to maximize the probability of the observed data. Because products of probabilities underflow, we maximize the **log-likelihood**, i.e. minimize the **negative log-likelihood (NLL)**.
- **Entropy** `H(p) = −Σ p log p` — average surprise. **Cross-entropy** `H(p, q) = −Σ p log q` — average surprise when reality is `p` but you predict `q`. With a one-hot target, cross-entropy = `−log q(correct class)`. **KL divergence** `KL(p‖q) = H(p,q) − H(p) ≥ 0` measures how far `q` is from `p`; it shows up in RLHF (Week 7) as a leash keeping the tuned model close to the reference.
- **Perplexity** = `exp(average NLL per token)`. A perplexity of 10 means the model is, on average, as uncertain as choosing uniformly among 10 tokens.

## 1.6 Numerical computing in practice

Computers use floating point. `float32` has ~7 decimal digits of precision; `bfloat16` keeps float32's exponent range with fewer mantissa bits, which is why it's the standard training dtype on modern accelerators; `fp16` has more precision bits but a narrow range and needs loss scaling. Lessons:

- Never compute `log(softmax(x))` naively — use the fused `log_softmax` / `cross_entropy`, which use the **log-sum-exp trick**.
- **Vectorize**. A Python loop over a million elements is ~100× slower than one NumPy call because the work moves into optimized C/BLAS. On GPUs the gap is larger still.
- Check for `nan`/`inf` early; most are caused by `log(0)`, division by ~0, or a learning rate that's too high.
