## 3.1 From linear models to neural networks

A **multilayer perceptron (MLP)** stacks linear layers with nonlinear **activation functions**:

```
h₁ = φ(x W₁ + b₁)
h₂ = φ(h₁ W₂ + b₂)
logits = h₂ W₃ + b₃
```

Without φ, the composition of linear maps is still linear — no added expressive power. With it, MLPs are **universal approximators**: wide enough networks can approximate any continuous function on a bounded domain. Depth matters in practice because deep networks represent hierarchical features far more *efficiently* than shallow ones.

Common activations:
- **ReLU** `max(0, x)` — cheap, non-saturating for x>0; can "die" if a unit is always negative.
- **GELU** `x·Φ(x)` — smooth ReLU; used in BERT/GPT-2.
- **SwiGLU** — a gated unit `(xW ⊙ swish(xV))W₂` used in the feed-forward blocks of most modern LLMs (LLaMA family and many others).
- **Sigmoid / tanh** — saturate (gradients → 0 for large |x|), so they're mostly used for gates and outputs now.

## 3.2 Backpropagation and computational graphs

Every computation builds a **directed acyclic graph** of operations. **Forward pass**: compute values node by node. **Backward pass**: starting from `∂L/∂L = 1`, propagate gradients in reverse topological order, each node multiplying the incoming gradient by its *local* derivative and passing it to its inputs (**the chain rule**). When a value feeds multiple consumers, its gradients **add**.

Worked micro-example: `L = (a·b + c)²` with `a=2, b=3, c=1`.
- Forward: `d = a·b = 6`, `e = d + c = 7`, `L = e² = 49`.
- Backward: `∂L/∂e = 2e = 14`; `∂L/∂d = 14 · 1 = 14`; `∂L/∂c = 14`; `∂L/∂a = 14 · b = 42`; `∂L/∂b = 14 · a = 28`.

This is **reverse-mode automatic differentiation**: one backward pass yields gradients for *all* parameters at roughly the cost of ~2 forward passes. That asymmetry (one scalar loss, billions of parameters) is why reverse mode is used in deep learning. PyTorch's `loss.backward()` and JAX's `grad` do exactly this.

Memory note: the backward pass needs the forward **activations**, so training memory ≈ parameters + gradients + optimizer state + activations. **Activation checkpointing** trades compute for memory by recomputing activations during backward.

## 3.3 Optimizers

- **SGD with momentum**: accumulate a velocity `v ← βv + g; θ ← θ − ηv`; smooths noisy gradients.
- **Adam**: keeps exponential moving averages of the gradient (`m`, 1st moment) and squared gradient (`v`, 2nd moment), with bias correction, and steps `θ ← θ − η · m̂ / (√v̂ + ε)`. Effectively a per-parameter adaptive learning rate. Typical β₁=0.9, β₂=0.95–0.999.
- **AdamW**: Adam with **decoupled weight decay** (`θ ← θ − ηλθ` applied separately). The default for training transformers.
- Memory cost: Adam stores 2 extra values per parameter. In mixed precision with fp32 master weights, a common rule of thumb is **~16 bytes per parameter** for weights + grads + optimizer state (before activations). A 7B model → ~112 GB just for that — which is why full fine-tuning needs multiple GPUs and why LoRA exists.

**Gradient clipping** (cap the global gradient norm, often at 1.0) prevents occasional huge updates from destroying training.

## 3.4 Initialization and normalization

If weights are too large, activations explode layer by layer; too small, they vanish. **Xavier/Glorot** init scales variance by `1/fan_avg` (for tanh); **He/Kaiming** init uses `2/fan_in` (for ReLU). Goal: keep activation variance roughly constant through depth.

**Normalization** re-standardizes activations:
- **BatchNorm**: normalize across the batch; great for CNNs, awkward for variable-length sequences.
- **LayerNorm**: normalize across features of each token — standard in transformers.
- **RMSNorm**: LayerNorm without mean-centering (`x / RMS(x) · g`); cheaper; used in most modern LLMs.

**Residual connections** `y = x + F(x)` give gradients a direct "highway" back through the network and are the single most important trick that makes very deep networks trainable (ResNet, 2015; every transformer since).

## 3.5 Regularization for deep nets

- **Dropout**: zero each activation with probability p during training and scale the survivors by 1/(1−p) ("inverted dropout"), so nothing changes at inference.
- **Weight decay** via AdamW.
- **Label smoothing**: train on slightly softened targets.
- **Early stopping** and **data augmentation**.

Large LLM pretraining often uses little or no dropout because the dataset is so large that each example is seen ~once — overfitting is not the binding constraint; compute is.

## 3.6 PyTorch essentials

```python
import torch, torch.nn as nn, torch.nn.functional as F

class MLP(nn.Module):
    def __init__(self, d_in=784, d_h=256, n_cls=10):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(d_in, d_h), nn.GELU(),
                                 nn.Linear(d_h, d_h), nn.GELU(),
                                 nn.Linear(d_h, n_cls))
    def forward(self, x):
        return self.net(x)

model = MLP()
opt = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.01)
for x, y in loader:
    logits = model(x)
    loss = F.cross_entropy(logits, y)   # takes raw logits!
    opt.zero_grad()
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    opt.step()
```

Gotchas: `F.cross_entropy` expects **logits**, not softmax outputs; forgetting `zero_grad()` accumulates gradients; call `model.eval()` and `torch.no_grad()` for inference (disables dropout, saves memory); move both model and data to the same device.

## 3.7 Debugging neural networks

A professional checklist (adapted from Karpathy's "Recipe for Training Neural Networks"):
1. Check the initial loss: for C classes with random init it should be ≈ `ln C`.
2. **Overfit a single batch** to ~zero loss. If you can't, there's a bug.
3. Visualize inputs right before they enter the model.
4. Monitor gradient norms and activation statistics per layer.
5. Change one thing at a time; keep a log of experiments (Weights & Biases, MLflow, or a spreadsheet).
