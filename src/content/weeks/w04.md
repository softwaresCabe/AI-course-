## 4.1 Representing text for a model

Neural networks consume numbers, so text must be converted to integer IDs (**tokenization**) and then to vectors (**embeddings**). These choices quietly shape cost, multilingual quality, arithmetic ability and even security.

Options:
- **Characters/bytes**: tiny vocabulary, very long sequences (attention cost grows with length).
- **Words**: short sequences, but huge vocabularies and no way to handle unseen words.
- **Subwords** (the standard): frequent words are single tokens; rare words split into pieces. Rule of thumb for English with modern tokenizers: **~4 characters ≈ 1 token**, or ~0.75 words per token.

## 4.2 Byte-Pair Encoding (BPE)

BPE (Sennrich et al., 2016; byte-level variant in GPT-2) builds a vocabulary bottom-up:
1. Start with the base alphabet — for **byte-level BPE**, the 256 possible bytes, so *any* string is representable (no "unknown" token).
2. Count all adjacent symbol pairs in the training corpus.
3. Merge the most frequent pair into a new symbol; record the merge.
4. Repeat until the vocabulary hits the target size (e.g. 50k–200k).

To encode new text, apply learned merges in order. Related schemes: **WordPiece** (BERT) and **Unigram LM** (SentencePiece), which prunes a large vocabulary by likelihood.

Consequences you'll actually hit as an engineer:
- **Cost & limits are in tokens**, not characters. Non-English languages and code often use more tokens per character → higher cost and smaller effective context.
- **Number handling**: "1234567" may split into odd chunks, one reason LLMs historically struggled with arithmetic.
- **Leading spaces** are part of tokens (" hello" ≠ "hello"), which matters for prompt templates and logit bias.
- **Glitch tokens** and special tokens (`<|endoftext|>`, chat-template markers) can be attack surfaces — never let user input inject raw special tokens.

## 4.3 Embeddings

An **embedding table** is a learned matrix `E: (vocab_size, d_model)`; token ID `i` maps to row `E[i]`. It's mathematically identical to multiplying a one-hot vector by `E`, but implemented as a lookup.

Embeddings place semantically similar items near each other. **word2vec** (Mikolov et al., 2013) showed that predicting context words produces vectors with linear structure (`king − man + woman ≈ queen`, approximately). Modern **sentence/document embedding models** (trained with contrastive objectives) produce one vector per passage — the foundation of semantic search and RAG (Week 10).

**Weight tying**: many LMs reuse the input embedding matrix as the output projection (`logits = h Eᵀ`), saving parameters.

## 4.4 Language modeling before transformers

- **n-gram models**: estimate `p(wₜ | wₜ₋ₙ₊₁…wₜ₋₁)` from counts, with smoothing. Fast, interpretable, but can't generalize beyond seen contexts and context is tiny.
- **Neural LMs** (Bengio et al., 2003): embed the previous n tokens, feed an MLP, predict the next token — generalizes via embeddings.
- **RNNs**: process tokens sequentially, carrying a hidden state `hₜ = tanh(W hₜ₋₁ + U xₜ)`. In theory unbounded context; in practice gradients vanish over long ranges.
- **LSTMs/GRUs**: gated cells that preserve information over longer spans. Dominated NLP ~2014–2017 (translation, speech).

Two fundamental RNN limitations motivated transformers:
1. **Sequential computation**: step t depends on step t−1, so you can't parallelize across the sequence during training — poor GPU utilization.
2. **Information bottleneck**: everything about the past must squeeze through one fixed-size hidden vector.

## 4.5 The attention idea

**Attention** (Bahdanau et al., 2014) was introduced for translation: instead of compressing the source sentence into one vector, let the decoder look back at *all* encoder states and take a **weighted average**, with weights computed from relevance.

The modern formulation — **scaled dot-product attention**:

```
Attention(Q, K, V) = softmax( Q Kᵀ / √d_k ) V
```

- **Queries** `Q`: what each position is looking for.
- **Keys** `K`: what each position offers to be matched against.
- **Values** `V`: the content actually retrieved.
- `QKᵀ` gives an (n × n) matrix of similarity scores; softmax over each row turns them into weights summing to 1; multiplying by `V` mixes values.
- Dividing by `√d_k` keeps the dot products from growing with dimension, which would push softmax into saturated, near-one-hot regions with tiny gradients.

Analogy: a **soft, differentiable dictionary lookup**. A Python dict returns the value whose key matches exactly; attention returns a blend of values weighted by how well each key matches the query.

In **self-attention**, Q, K and V all come from the same sequence (`Q = XW_Q`, `K = XW_K`, `V = XW_V`), letting every token gather information from every other token in one parallel step. Cost: **O(n²·d)** time and O(n²) memory for the score matrix — the reason long context is expensive and why techniques like FlashAttention (Week 8) matter.

## 4.6 Causal masking

For language modeling, position t must not see tokens after t (that would be cheating — the answer is in the input). We add a **causal mask**: set scores for j > i to −∞ before softmax so their weights become 0. This lets us train on all positions of a sequence *in parallel* while preserving the autoregressive factorization from Week 1 — "teacher forcing" with full parallelism, which RNNs could not do.
